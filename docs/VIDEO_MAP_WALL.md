The builder rejects a source located in the repository or output tree. It decodes
frames and PCM in an external temporary directory, never copies the MP4 into the
repository, derives frame count from actual decoded output, and writes a source
SHA-256 plus measured dimensions/rate/durations to
`minecraft/video_screen/build_report.json`. OGG output uses FFmpeg bitexact flags.
Pillow/FFmpeg version changes can still change generated bytes; pixel/audio
comparison should precede asset churn.

104.420136 s. Output: 20 fps, 2,088 frames, 104.4 s loop, 21 RGB atlases at
660x380, one real mono OGG. Media totals 9,418,693 bytes with this toolchain.
Each 64x36 frame has one-pixel extruded padding. The final audio is trimmed/padded
to exactly the video loop period. A truly silent source produces no audio entry,
not a fake silent replacement track.

## Playback and Audio

Volatile cold state is OFF. Every ON starts frame zero. One server-synchronized
integer entity property selects the frame, atlas, and UV. A real-time media clock
keeps visual position aligned with audio even when server ticks slow down.
Playback wraps to zero at the measured output duration. OFF resets position and
stops each retained sound handle. Missing/unloaded helper entities fail to OFF;
chunk reload recovers to OFF without duplicate helpers. Script startup removes
old display helpers and clears only the video's sound ID on each player.

Audio uses only `Player.playSound`, never world/dimension broadcast or global
music APIs. Each eligible player owns a retained SoundInstance. Joiners start
muted, seek to the current position, and unmute. The front (+Z) hemisphere within
16 blocks of the screen center is eligible; volume decreases with distance and
is updated as players move. Exiting/dimension change/death/logout stops that
player's handle. Loop boundaries recreate handles at the current media position.
No undocumented seek parameter is passed to playSound. Unsupported SoundInstance
methods fail explicitly and stop audio rather than pretending synchronization.

## Map Recalculation Limitation

There is no documented public operation for recalculating the terrain pixels of
an existing filled map in the reviewed 2.11-beta declarations, block/item
component listings, or vanilla command reference. BlockMapColor changes a block's
map color, not a filled map's pixels. ExplorationMapFunction creates loot maps,
not an update of the original map. We therefore implement detection and re-scan
only. No private NBT, invented API, map replacement, frame destruction, or fake
success indicator is used.

- [Public block components](https://learn.microsoft.com/en-us/minecraft/creator/scriptapi/minecraft/server/blockcomponenttypes?view=minecraft-bedrock-experimental)
